# Embedded C Development Standards

本仓库集中管理嵌入式C项目的EPR编程规则、EDI开发指导、格式配置、维护工具、模板、教学示例和审查记录。仓库不包含产品源码，也不保存编程规则的原始依据文件。

## 正式文件入口

- [嵌入式编程规则手册](1.编程规范/嵌入式编程规则手册.md)：EPR 1.0.2。
- [嵌入式程序开发指导书](2.开发指导/嵌入式程序开发指导书.md)：EDI 1.0.2。
- [维护状态](docs/维护状态.md)：当前限制、待办事项和验证边界。
- [规则决策记录](docs/规则决策记录.md)：仓库结构、版本和职责边界的决策依据。
- [ZL501 项目版](ZL501/README.md)：独立 EPR/EDI 2.0.0 正式版；不改变通用版 1.0.2。

## EPR与EDI的职责

### EPR：代码合规规则源

EPR负责嵌入式C代码的语言、命名、类型、接口、模块、格式、内存、并发、错误处理、文档最低要求及验证规则。仓库根目录的`.clang-format`和`.editorconfig`由EPR中的工具配置基线生成，并通过`1.编程规范/编程规则版本绑定.json`绑定版本和SHA-256。

### EDI：开发实施指导源

EDI负责需求至交付的开发阶段、Service/Composite/Atomic函数分级、模块资料库、模板、教学示例、AI初审、人工审核以及交付过程。EDI引用EPR编号，不得另行制定与EPR冲突的代码合规要求。

### 优先级与重叠处理

代码合规事项以EPR为准；开发过程和交付组织事项以EDI为准。发现重复、冲突或边界不清时，先登记到`docs/规则决策记录.md`，经人工确认后再修改正式文件。1.0.2已完成职责收敛：EPR第18章只保留规则组合映射及EDI资产入口，完整模板和教学示例由EDI统一维护；EDI通过稳定编号引用EPR，不再维护重复技术判据。

## 仓库结构

```text
1.编程规范/   EPR、绑定记录、操作说明、维护工具及历史验证资料
2.开发指导/   EDI、需求决策、审查记录、模板及完整示例
docs/         当前维护状态和跨文档决策
```

原始依据文件、意见稿、本地工具依赖、缓存和产品源码不进入本仓库。

## 常用检查

在仓库根目录使用Python 3.10或更高版本执行：

```powershell
python "1.编程规范/维护工具/coding_rules.py" check
python "1.编程规范/维护工具/coding_rules.py" format-check `
    --clang-format "<clang-format 21.1.0可执行文件>"
```

维护工具的Python依赖见`1.编程规范/维护工具/format-validation-requirements.txt`。参数化模板在替换`{{...}}`占位符前只执行文件字节检查，实例化后必须执行完整格式检查。格式检查只证明列明的格式和文件字节条件，不证明目标DSP、ABI、实时性或全部语义规则符合要求。

## 变更流程

1. 完善任务：补齐变更范围、依据、版本影响和验证条件。
2. 命令确认：列出将修改的文件、版本、检查及Git操作。
3. 执行确认：取得用户明确确认后才能修改或发布。

EPR变更必须通过维护工具同步版本、配置和绑定记录；EDI变更必须同步模板、示例、审核记录及相关引用。AI可以初审，但不能代替人工批准正式发布。
