# ZL501 项目版 EPR / EDI

本目录的版本序列与仓库根部通用 EPR / EDI 独立。项目版最初由通用 1.0.2 派生，并依据《编程开发规范20261016》正文进行项目化；截图仅用作示例，原始 DOCX 不纳入仓库。2.0.0 为不兼容项目化版本；3.0.0 对本次与 `main` 冲突的要求以 `main` 为准。

> ZL501 2.1.0 依据 `Nan.Wang` 分支提交 `76f04be` 适配 PIB 规则，按项目既有编号重新映射，并于 2026-10-23 经 Nan.Wang 人工评审批准。项目版本与配置绑定独立于通用版。

> ZL501 3.0.0 依据 `main` 提交 `3a6e1b3` 适配保护宏、文件头、注释语言和 `@category` 要求；与 2.1.0 冲突之处以 `main` 为准，EPR-DOC-007 的强制中文 `@note` 标签按正文保留。Nan.Wang 于 2026-10-28 审查通过并授权提交、上传 GitHub。

本目录从通用版复制的 `需求与决策记录.md` 和 `完整审查记录.md` 仅保留 1.x 历史，不继承其对旧源码的批准。ZL501 项目版五个示例函数分类于 2026-10-21 获 Nan.Wang 人工批准，独立记录于本目录。EPR 的格式及哈希检查不能证明目标 DSP、TI 工具链、ABI、ISR、DMA、栈、WCET 或实时安全已验证。

在仓库根目录可执行：

```powershell
python "ZL501/1.编程规范/维护工具/coding_rules.py" check
python "ZL501/1.编程规范/维护工具/coding_rules.py" format-check `
    --clang-format "C:\Program Files\LLVM\bin\clang-format.exe"
```

后续修改函数实现、职责、调用关系或可见性时，应重新审核分类；不得自动沿用本次批准。

2.1.0 的 PIB 显式标记检查可运行 `python "ZL501/1.编程规范/维护工具/coding_rules.py" pib-check`；聚焦单元测试为同目录的 `test_pib_rules.py`。扫描为零不能证明不存在未识别的集成缺口。
